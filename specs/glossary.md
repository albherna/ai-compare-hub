# Glosario

## 1. Propósito

Este documento define los términos clave del dominio de negocio y del producto AI Compare Hub. Su finalidad es garantizar un lenguaje ubicuo consistente entre producto, negocio, arquitectura, UX y análisis.

## 2. Términos de negocio

### AI Tool (Herramient IA)
Una herramienta digital basada en Inteligencia Artificial que ofrece una capacidad funcional específica, como generación de texto, imágenes, audio, visión, código o automatización.

### Category (Categoría)
Clasificación funcional de una herramienta según su propósito principal. Ejemplos: Chat, Código, Diseño, Video, Audio, Investigación, Productividad, Agentes.

### Capability (Capacidad)
Funcionalidad o competencia que una herramienta puede ejecutar. Ejemplos: generación de texto, edición de imágenes, transcripción, análisis de datos, automatización de flujo de trabajo.

### Benchmark (Benchmark)
Medición o comparación de rendimiento y cualidades de una herramienta bajo criterios evaluables. Incluye velocidad, calidad, costo, fiabilidad o adecuación para casos concretos.

### Comparison Matrix (Matriz de comparación)
Representación estructurada que compara dos o más herramientas con base en atributos homogéneos, como precio, capacidades, limitaciones y uso recomendado.

### Feature (Funcionalidad)
Elemento concreto de la oferta de una herramienta, como soporte de plugins, API, modo de colaboración, integración con GitHub, traducción en tiempo real o editor multimodal.

### Pricing Plan (Plan de precios)
Modelo comercial asociado a una herramienta, incluyendo tipos de usuarios, límites, costos, acceso a funciones premium y condiciones de uso.

### User Profile (Perfil de usuario)
Conjunto de atributos que describen el tipo de usuario, sus objetivos, nivel de experiencia y contexto de uso. Ejemplos: desarrollador, marketer, diseñador, estudiante, equipo SMB.

### Recommendation (Recomendación)
Sugerencia de una o varias herramientas según el perfil del usuario, el caso de uso y las restricciones de costo o capacidad.

### Comparison Session (Sesión de comparación)
Instancia en la que un usuario selecciona dos o más herramientas y observa sus diferencias a través de una vista comparativa.

### Tool Detail Page (Página de detalle)
Vista específica de una herramienta con sus atributos, capacidades, benchmarks, planes y contexto de uso.

### Discovery (Descubrimiento)
Proceso por el cual el usuario explora herramientas mediante navegación, filtros, búsquedas o recomendaciones.

## 3. Términos de producto

### Catalog
Colección centralizada de herramientas IA disponibles en la plataforma, con metadata estructurada y actualizada.

### Filter (Filtro)
Criterio de búsqueda para acotar la lista de herramientas. Ejemplos: categoría, uso, rango de precio, nivel de experiencia, integración disponible.

### Search
Acción mediante la cual un usuario localiza herramientas por nombre, categoría, caso de uso o palabra clave.

### Score
Valor atribuido a una herramienta en un criterio específico, como usabilidad, rendimiento o coste/beneficio.

### Persona
Representación sintética de un tipo de usuario que ayuda a definir necesidades, objetivos y escenarios de uso.

### Use Case (Caso de uso)
Escenario concreto donde una herramienta aporta valor. Ejemplos: redacción de contenido, programación asistida, generación de imágenes, transcripción, automatización de soporte.

## 4. Términos técnicos

### Metadata
Información estructurada que describe una herramienta: nombre, categoría, fecha de actualización, proveedor, modelos compatibles, nivel de soporte, planes y capacidades.

### Benchmark Source
Fuente externa o interna de la que se extraen las comparativas. Puede ser un proveedor de datos, una evaluación editorial o una métrica de desempeño internalizada.

### Normalized Data
Datos convertidos a un formato común para permitir comparaciones equitativas entre herramientas con atributos distintos.

### Content Integrity
Estado de confiabilidad y consistencia del contenido publicado en la plataforma, con reglas de validación y actualización.

## 5. Lenguaje ubicuo

El lenguaje ubicuo del producto se utiliza de forma consistente en toda la experiencia:

- Buscar herramienta
- Comparar IA
- Filtrar por categoría
- Ver capacidades
- Revisar benchmarks
- Consultar precios
- Recibir recomendación
- Evaluar adecuación por perfil
- Guardar comparación
- Explorar por caso de uso

## 6. Definiciones clave para el negocio

### Herramient recomendada
Una herramienta que, por perfil, caso de uso y restricciones del usuario, presenta el mejor ajuste potencial.

### Herramient comparable
Una herramienta que comparte capacidades o aporta alternativas reales para un mismo caso de uso.

### Herramient premium
Una herramienta con capacidades avanzadas o límites de uso más amplios que normalmente requieren suscripción.

### Herramient de productividad
Una herramienta diseñada para apoyar tareas repetitivas, automatización o eficiencia operativa.

### Herramient creadora
Una herramienta centrada en generar contenido multimedia, texto, imágenes, video o audio.

## 7. Ambigüedades resueltas

Para evitar interpretaciones inconsistentes:

- “Benchmark” se refiere a una comparación de capacidades, no a una prueba técnica exhaustiva de laboratorio.
- “Precio” incluye tanto modelos freemium como planes de suscripción, siempre con referencia explícita a la estructura de cada proveedor.
- “Recomendación” no es una decisión absoluta: es una sugerencia contextual basada en perfil y objetivos.
- “Categoría” se define por caso de uso principal, no por marca o proveedor.

## 8. Términos excluidos del dominio principal

Estos conceptos no forman parte del core product de la primera versión, aunque podrían incorporarse más adelante:

- Marketplace transaccional
- Compra de licencias dentro del sitio
- Oferta de servicios profesionales personalizados
- Integración nativa con modelos privados de clientes empresariales

## 9. Convenciones de estilo

- Se documentará todo el contenido con lenguaje neutral, claro y orientado al usuario.
- Los nombres de herramientas se escribirán con el formato comercial original del proveedor.
- Las categorías se usarán de forma consistente en filtros, listados y comparativas.
- Los resultados comparativos se etiquetarán explícitamente como “datos estructurados”, “estimación” o “recomendación” cuando correspondan.
